# izzna 功能實作狀態

依 `docs/IZZNA_PRODUCT_SPEC.md`、程式及本次瀏覽器操作檢查整理；「Demo」指固定資料，並非完成正式 AI 功能。測試於 Chromium 375px 與 1440px，網址包含 repository 子路徑；各狀態不是對未來功能的承諾。

| 編號／功能 | 實際狀態與證據 | 與規格的差距及依賴 | 下一階段與可驗收條件 |
| --- | --- | --- | --- |
| F01 情境與自由聊天 | **部分／Demo**：四情境由 JSON 驅動，實測進入、輸入及模擬回覆；介面標示 Demo。 | 未理解上下文，未提供自由聊天；正式聊天依賴安全後端與 LLM。 | 建立後端 PoC；三輪回覆能引用前文、分享與自然接話，情境切換仍正確。 |
| F02 不知道要說什麼 | **部分／Demo**：每情境 3 個固定中文方向，與語言提示分開；實測開關。 | 不依最新回合調整；依賴對話上下文與 LLM。 | 輸入不同話題後給 2–3 個相關方向，不修改草稿或傳送。 |
| F03 傳送前中文查詢 | **部分／Demo**：獨立 JSON 六組詞語、未知詞回報、標記查詢、主動填入與未解決標記阻擋送出；實測查詞、重複查、草稿保留及多標記。 | 只有精確收錄詞；無自由意圖、上下文理解或完整參考句；正式版依賴後端及 LLM。 | 安全後端提供結構化上下文提示；查詢、開關及找不到時均保留草稿，不自行傳送。 |
| F04 點詞解析 | **部分／Demo**：角色訊息預整理詞語可點，顯示原形、詞幹、詞尾、語氣及例句；實測視窗與 Escape。 | 未支援任意詞的切詞及即時解析，也未涵蓋所有詞性或使用者訊息；依賴形態分析／後端。 | 驗證詞形及多義，點詞、鍵盤開關、保留草稿並正確呈現縮約。 |
| F05 漸進提示 | **部分／Demo**：固定單字、文法、句型可各自展開；實測不覆蓋輸入。 | 未記錄提示種類與次數，無動態提示；紀錄依賴 F07。 | 各提示獨立可關閉；記錄種類和次數，查看不等於答錯。 |
| F06 聊天回饋與回顧 | **尚未實作**：一般 Demo 不逐句糾錯。 | 缺主動檢查、證據連結及聊天後回顧；依賴對話、後端／LLM、紀錄。 | 回顧能指向真實句子及提示，不虛構錯誤或把查詢視為答錯。 |
| F07 個人學習記憶 | **尚未實作**：重新整理或換情境即重置。 | 無持久化、查詢紀錄與錯誤分類；依賴儲存設計與事件紀錄。 | 真實紀錄建立、重啟後讀取；提示與錯誤分開且不憑空新增。 |
| F08 Planning 與針對性複習 | **尚未實作**。 | 依賴 F07 真實紀錄、練習選擇及 F01 對話；不可隨機宣稱個人化。 | 查過 쉬다 後在新情境實際練習，成功獨立使用後更新優先度。 |
| F09 朗讀、OCR 等 | **尚未實作**。 | 依賴合適的 TTS、截圖處理／OCR 與隱私設計。 | 後續分別驗證詞句朗讀、語音選擇及截圖保留上下文。 |

## AGENTS.md 延伸性驗證

Commit `71d8a60` 僅新增 `data/scenarios/restaurant-order.json` 並更新索引；沒有複製 HTML 或修改共用 JavaScript。四個情境在該 commit 的 Chromium 測試均能進入、聊天並開啟詞語解析。資料分離、索引欄位與相對路徑規則足以完成主要擴充；韓語語體規則允許餐廳服務場合採敬語。

歧義：最小 schema 的示例未包含實際 Demo 送出訊息必須使用的 `fallback_replies`，雖有文字描述仍未規定必填；首頁圖示由 `js/app.js` 固定依序分配，而非讀取各情境的 `emoji`，新增第四個情境時沿用既有圖示，僅修改 JSON 無法指定首頁圖示。需日後明確 schema 與圖示來源，不影響聊天載入。

## 建議順序

1. 先做安全 Python 後端與 F01／F03 的小型 LLM 可行性測試，驗證多輪對話與結構化提示，保留靜態 Demo。
2. 定義 F07 可持久化的會話與提示事件，再以真實資料完成 F06 回顧。
3. 以紀錄實作 F08 的跨情境重練並測試優先度，並持續驗證 F04 韓語解析品質。
4. 核心閉環穩定後再評估 F09 語音與 OCR。
